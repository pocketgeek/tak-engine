# Sim/render decouple plan

Generated by the map-decouple-surface workflow (2026-09-08). The fix for the residual
16-27ms sim-tick stumbles: run the sim on its own 30Hz thread, render from an immutable
per-tick snapshot + interpolation. Staged so each step is shippable + determinism-verifiable.

I have verified the structures. Here is the concrete, staged implementation plan.

# Sim-thread decouple: implementation plan

Grounding facts confirmed in-tree: `Interp` is `src/client/main.cpp:6935`; `interp_`/`interpTickMs_`/`interpTickDurMs_`/`interpAlpha_` at `6936-6939`; `visUnits_` is `std::vector<const Unit*>` at `5414` populated `4015-4022` and dereferenced on the worker pool at `4072-4076`; `captureInterp` `3488-3503`; `interpPose` `3508-3521`; `mpStep` `2694-2849` with the per-bundle `simTick` lambda `2702-2730`; `simStep` `3319-3482`; `cosmeticStep` `3527`. Sim types: `Unit` `sim.h:212-286`, `Order` `193`, `Feature` `293`, `Projectile` `304-316`, `Player` `424-458`, `HitFx` `677`.

The whole plan rests on one inversion: **the render thread must never dereference anything that lives in `world_`.** Everything it reads today is replaced by an immutable, per-tick, render-owned snapshot published at the tick boundary, plus the already-existing `interp_` pose buffer (which is itself made a published double-buffer).

## 1. THE SNAPSHOT

One versioned bundle, `struct Frame`, produced by the sim thread at the end of each processed tick and published atomically. All render reads resolve against the currently-published `Frame`. Put the definitions in a new header `src/client/rendersnapshot.h` (render-owned, no sim mutation), included by `main.cpp`.

### 1a. Per-unit record — `struct UnitR` (id-indexed, dense, `id==index+1` preserved)

The snapshot is a `std::vector<UnitR>` indexed by unit id exactly like `interp_` already is, so `geomIndex_`/`visUnits_` and every `world_.unit(id)` HUD chase becomes an index into this array. Fields, grouped by the read that needs them:

Pose / identity (immutable-type carried by pointer so the record is self-contained):
- `int id`
- `const tak::sim::UnitType* type` — pointer is set once at spawn, never re-pointed by `tick` (confirmed `sim.h:215`); copying it makes the record touch no `world_`. All the `type->…` reads (name, maxHp, maxMana, weapons, footX/footZ, canFly, cruiseAlt, canMove, maxVel, isBuilder, canTransport, transportCap, canCloak, onOffable, canReclaim, side, buildCost, buildTime, workerTime, weapon.damage, veteranModel) stay off the pointer — immutable game data, safe.
- `float x, z, heading` — **latest-tick (curr) values**, for the RAW reads that bypass interp today: `wallOcclusionY` (`6074/6101/6144`), `uLiftX/uLiftY` (`6783-6784`, called at cull `4002-4003`), frustum cull (`4002-4003`), `flyerAltAt` (`6799`), minimap dots, all hit-test/proximity scans. **Interpolated pose still comes from `interp_`** (see 1e) — these curr x/z are only for occlusion/cull/hit-radius where one-tick staleness is invisible.

Mutated-per-tick scalars/flags (all confirmed sim-written; **no interp**, latest-tick is correct):
- `int player` — **changes on capture/charm** (`captureProg` completes in `tick`), a real race, not theoretical. Colour slot, disco/headbang gating, allied-cull all derive from this.
- `float hp, mana; int veteran, xp`
- `bool underConstruction, buildBegun, cloaked, cloakOn, active`
- `int weaponSlot, stance`
- `int8_t squad`
- `float deadFor` + derived `bool alive` (`deadFor<0`) — death-anim/corpse edge detection
- `int inTransport` + derived `bool embarked`
- `bool moving, walking` — **derived bools only**; never expose `orders`/`speed` (both mutate every tick; `orders` is a vector → resize UB). Computed sim-side from `u.moving()`/`u.walking()` (`sim.h:282/285`).
- `float frozenFor, stonedFor, paralyzedFor` (or a precomputed status enum) — for `unitStatusText` (`8383-8405`)
- one-tick **events** (see §3 event-once discipline): `bool justFired`, `int justBuilt` (`sim.h:250/271`)

Builder / production / HUD-chase state (the reason the array needs id lookup, not just index-by-selection):
- `int buildSiteId, repairId, reclaimId`
- `bool reclaimQueueEmpty`
- `const UnitType* repeatType`
- `std::vector<const UnitType*> buildQueue` (copy — small; `sim.h:269`) + `float buildProgress`. This backs the train bar and lets render compute the per-icon queued-count badge (`world_.queuedCount` at `9965`) and `+++` marker (`9954`) without calling into `World`.
- `std::vector<int> cargo` (or just `int cargoCount` — LOAD/UNLOAD gating at `7982-7984`, hover at `4915` need only non-empty; keep ids if any overlay needs them)
- orders, snapshotted as a **small value list** `std::vector<OrderR>` where `OrderR { float x,z; int targetId; uint8_t flags; }` packing load/unload/attackMove/patrol/guard from `Order` (`sim.h:193-205`). Backs selection brackets (`4369-4400`), attack-target brackets (`4402-4419`), status text, cursor preview. Never read `u.orders` live.

Precomputed convenience:
- `bool alliedToLocal` — fold `world_.allied(player, localPlayer_)` per unit at capture time (team membership can change via `setTeam`; `team` field `sim.h:446`). Removes the per-unit `world_.allied` call in the fog cull (`3993`) and minimap.

### 1b. Global player table — `std::array<PlayerR, kMaxPlayers>` + `int numPlayers`

`struct PlayerR { float mana, storage, income; int kills, team; bool defeated; int unitCount; bool disco, headbang; }`. Captured each tick from `Player` (`sim.h:424-458`). Feeds mana readouts (`10006`, `8104-8157`, `4522`), scoreboard (`9675-9779`), and the disco/headbang gating (`discoLeft`/`headbangLeft` decremented every tick at `sim.cpp:2271-2272` → snapshot as the two bools). `localPlayer_` index stays render-owned.

### 1c. Projectiles — `std::vector<ProjectileR>`

Full copy of `world_.projectiles()` each tick (`x,z,vx,vz,age,flight,fx,fromId,targetId`, `wsrc` pointer as-is into the immutable Weapon registry; `Projectile` `sim.h:304-316`). **Mandatory copy, not optional**: sim `push_back`s (`sim.cpp:1339`) and `erase_if`s (`sim.cpp:2386`) every tick → the backing array reallocates under a live render iterator (UB, `4246-4316`). No interp (projectiles advance per tick; optional later: extrapolate `x += vx*alpha`).

### 1d. Features + fog — `struct WorldGeomR`

- Features: `std::vector<FeatureR>` `{ int id; float x,z; int fx,fz; bool alive; }`. `features_` is setup-only (`addFeature` only from `matchsetup.cpp:241`), so **only `.alive` mutates** (reclaim, `sim.cpp:2024/2028`). Still snapshot the whole small vector each tick (simplest, correct) and expose a render-side `featureAliveAt(frame,x,z)` replacing `world_.featureAliveAt` (`3972`). Client `FeatureInst` art vector (`7322`) stays render-owned.
- **Fog** (shared cross-area deliverable): copy `vis_` grid + `visW/visH` + `visGen` into a render-owned buffer. `vis_` is viewer-local, **never hashed** (per CLAUDE.md), rebuilt in place ~4Hz (`sim.cpp:2063-2196`). Provide ONE render-side helper `cellVisible(frame.fog, x, z)` that replaces every `world_.cellVisible` call (`3993, 4247, 7093, 10393, 10416, 10442, 10529, 3561, 3846, …`). Gate the `fogTex_` re-upload on `frame.fog.visGen != fogTexGen_` (`10033`). `visW/visH` are match-constant — capture once.

### 1e. Pose double-buffer — `interp_` promoted to the handoff mechanism

`interp_` already IS the per-tick pose snapshot (prev/curr x/z/heading, `Interp` `6935`). Keep it, but **double-buffer** it: sim writes a back buffer in `captureInterp`, publishes the pointer with the `Frame`. `interpTickMs_`/`interpTickDurMs_` (`3501-3502`) publish together so `interpAlpha_` (`4025-4026`) matches the buffer generation. `interpPose`'s live fallback (`3509`) must read the record's curr x/z/heading, **not** `u.x/u.z/u.heading` — seed `interp_` from the snapshot so the smoothMotion-off path never touches `world_`. Position-like fields keep the shortest-path heading interpolation already at `3517-3520`.

### 1f. Session-config + status — published with the `Frame` header

`int outcome; int winningTeam; std::string netError; uint32_t netTick; int bufferedBundles; float behindSec; uint8_t gameSpeed; float actualSpeed; std::vector<std::string> notices;` — the scalar surface the render banners/debug HUD read (§2c). `spectating_/noFog_/replayMode_/localPlayer_/side_` are set once before the sim thread starts and are read-only thereafter (release fence at thread spawn) — not per-tick.

**Interp summary:** only x/z/heading interpolate (via `interp_`). Everything else is latest-tick. Projectiles, fog, features, all HUD scalars: no interp.

## 2. THREADING

### 2a. Handoff — sequence-locked double buffer, swap at tick boundary

Two `Frame` buffers owned by the sim thread; a `std::atomic<const Frame*> published_` (or a seqlock with a generation counter). The sim thread fills the back buffer during/after `simStep`+`captureInterp`, then does one release-store to publish. The render thread does one acquire-load at the **top of each rendered frame** and holds that pointer for the whole frame (so `hoverCursor`, `drawUnits`, minimap, HUD all see one consistent tick). `visUnits_`/`geomIndex_` then reference `frame->units[...]`, never `world_.units()`.

Because the sim can process several ticks between two rendered frames, publish only the **latest** tick's `Frame` for durable state — but per-tick **events** (hits/justFired/justBuilt) must not be dropped (§3). So the event channel is a separate drained queue, not the last-writer-wins `Frame`.

### 2b. Net I/O location

The whole InGame drain moves to the sim thread: `mpStep` (`2694-2849`) — `poll` → `desynced` → `sendCommands` → per-bundle `apply`/`applyEvent`/`simStep`/`sendHash`/`++netTick` → jitter-buffer pacing → spectator heartbeat → actual-speed → slow-guard. `simStep` (`3319-3482`) and `captureInterp` move with it. All pacing fields (`netDelay_`, `netAuto_`, `netBufReady_`, `netAccum_`, `netStepMs_`, `mpSlowSinceMs_`, `lastSpecAckMs_`, `netBench*`) become sim-thread-local. **`MpClient` has zero internal locking** (`src/net/client.*`: `poll()` at `client.cpp:38` mutates `bundles_/chat_/state_/gameSpeed_`) → the sim thread **exclusively owns `mp_` for the entire InGame session.** Render never calls `mp_` during play. The sim thread runs its own 30Hz×gameSpeed loop (the `SDL_GetTicks64` pacing at `2760-2778` stays), fully decoupled from render FPS.

The **lobby phase stays on the render/main thread** and calls `mp_` freely (`drawLobby 8961`, `drawBrowser/listGames 8993`, `drawRoom setSlot/startGame/kick 9376-9538`, lobby chat). This is safe only because the sim thread does not yet exist. `startMpGame` (`2578`, builds `world_`) runs on the main thread; the sim thread is spun up (or unpaused) at the **Starting→InGame transition when `mpSetupDone_` flips** (`3049/3067`).

### 2c. Render→sim: player input (`outbox_`) and chat

Replace the plain `outbox_` vector (written by ~25 `issue()` sites `2571`, read/cleared in `mpStep 2697`) with a **mutex-guarded FIFO command queue** (a small `std::mutex` + `std::vector<Command>`; contention is trivial — a handful of pushes per click, one swap per sim step). `issue()` (`2568-2573`) pushes; the sim thread swaps the whole queue out under the lock at the top of its step and hands it to `mp_->sendCommands()` in one batch — preserving FIFO and the once-per-step batching that build-line queues depend on. In-game **chat** (`input():2149 mp_->chat()`) and **menu/quit intent** (`menuRequested_ 2174`, `quitRequested_`) travel the same queue as tagged items so the sim thread issues `mp_->chat()` and observes the stop signal; render never touches `mp_`.

Crucially, `issue()` today **reads `world_`** to build commands (`world_.canPlace 2264`, `selectedBuilder()`, selection lookups). Those reads move onto the published `Frame` (the ghost/preview `canPlace` runs against the snapshot; the authoritative `canPlace`/target-scan for the actual Build/order emit is validated **on the sim thread** — see §2e). Only the finished `Command` crosses the queue.

### 2d. Sim→render: outcome / netError / chat / notices

- `outcome_` (`3386/3458/3470/3478`, read `4654/2174`), `winningTeam` (`4658`), `netTick_` (`4604`), `bufferedBundles`/`behindSec` (`4614`), `gameSpeed` (`3865`), `actualSpeed_`: publish in the `Frame` header (§1f); the trivially-scalar ones (`outcome`, `gameSpeed`, `netTick`, `actualSpeed`, `behindSec`) may alternatively be plain `std::atomic` for lower latency — either is fine.
- `netError_` (`std::string`, `2695/2696/2842`, read `4622`): not atomic → publish in the `Frame` under the same seqlock, or `atomic<bool> hasNetError_` + a small-mutex-guarded string.
- Received **chat** (`mp_->takeChat()` at `3935` races `poll()`): sim thread drains `takeChat()` right after each `poll` into a mutex-guarded render-facing queue; render's `draw()` drains THAT into `gameChat_` and ages it on the wall clock (aging stays render-side). Lobby `takeChat` (`8967`) stays render-owned (pre-handoff).
- `notice_` strings produced sim-side (`mpStep 2838`, `simStep 3342/3362`) push into a small render-visible queue; the timer countdown + draw stay render-side (`cosmeticStep:3623`, `draw:4644`).

### 2e. Input handlers that scan `world_` (pick-input area)

The coordinate transform (`pickWorld`/`heightAbove`/`terrainLift`, `6827/6737/6772`) touches only the immutable heightmap + render camera — **stays fully render-side, no snapshot**. Two categories for what handlers do with the world point:

- **Once-per-frame reads that cannot block** (`desiredCursor/hoverCursor 4886-4985`, `guiActiveButtons/renderGui 7954-8053`, selection & attack brackets `4369-4419`, drag-preview overlays `4322-4353`): read the published `Frame`. A shared snapshot-scan helper serves both `hoverCursor` and `rightClickOrder` since they mirror each other's scans.
- **On-input order emitters that want authoritative positions** (`rightClickOrder 2361`, `issueArmedOrder 7153`, `minimapOrder 7130`, `issueReclaimBox 2529`, build placement `2264/10131`, `issuePerUnit/selectWeapon/Stop 8238/7897/8170`): **post the intent** (world point + selection ids + modifiers) as a queued command item; the sim thread does the nearest-target scan against live `world_` (authoritative, non-interpolated) and emits. This keeps `applyCommand`/`apply` (`3078/3074`) strictly on the sim thread — the `!mp_` fallback, `replayStep 2880`, and local `update()→simStep 3869` paths (which currently mutate `world_` on the caller thread) all route through the sim-thread drain.

Convert `selectedBuilder()` (`8558`), `haveReclaimer()/firstReclaimer()` (`2511/2519`) to **return ids, not `Unit*`** (they currently hand back dangling pointers into `world_.units()`), backed by `Frame` lookups.

## 3. RACE / DETERMINISM HAZARDS

The sim tick sequence and `stateHash()` must stay byte-identical — the renderer only ever READS the `Frame`, never writes `world_`. Specific hazards and their removal:

1. **`world_.units()` reallocation** — `tick` `spawn()`/`erase` reallocates the vector, dangling every `visUnits_` raw pointer (deref'd on worker threads at `4075`). **Root cause of every field race.** Removed by `visUnits_` referencing `frame->units` (immutable, owned by the completed `Frame`); the sim can reallocate freely because the render holds a different buffer.
2. **`world_.unit(id)` dangling** — every HUD chase (`buildSiteId`, `repairId`, `order.targetId`, selection) returns a pointer into that vector. Removed by id-indexed `Frame::units` lookup.
3. **`orders`/`buildQueue`/`cargo`/`reclaimQueue` vector resize** under a render read → UB. Removed by snapshotting derived bools (`moving`) and value copies (`OrderR` list, `buildQueue` type-id copy, `cargoCount`).
4. **`projectiles_`/`vis_`/`hits_` reallocated or rebuilt in place every tick** → hard UB. Removed by whole-container copy into the `Frame` (projectiles, fog, hits).
5. **Per-tick event double-fire / drop.** `hits_` is cleared at tick start (`sim.cpp:2266`) and repopulated (`sim.cpp:1256`); `justFired`/`justBuilt` cleared at `sim.cpp:2264`. If the render consumes these per rendered frame it double-fires explosions/muzzle flashes; if the sim publishes only the latest `Frame` it drops events on multi-tick catch-up. **Fix:** carry hits + justFired/justBuilt in a **per-tick event queue** the render drains exactly once per tick (tag each event batch with `netTick`; drain by tick id, not by frame). This is separate from the last-writer-wins durable `Frame`.
6. **Render mutating `world_` from cosmetic code** — two existing violations: `world_.clearHits()` (`3568`) and `addFeature(corpse)→world_.nav().block()` (`3621→7509`). **DROP `clearHits`** (sim clears next tick). **Move corpse `addFeature`/nav-block to the sim thread** (it is a hashed nav mutation!) — keep only the render `FeatureInst` decal render-side. This is a latent determinism bug the decouple must fix, not introduce.
7. **`captureInterp` resize race** (`3490` resizes `interp_` to units+1) — removed by writing the back buffer and publishing atomically.
8. **`anims_` ownership** — COB VM is render-owned, keyed by `u.id`; safe, but its register/erase must be driven off the `Frame`'s spawn/death (justBuilt / alive edge), **not** live `world_`. `birthFx_`, `corpsed_`, `particles_`, `effects_`, `rings_` stay render-owned.
9. **`heightAbove` shared 1-entry memo** (`hMemoMap_/hMemoX_/…` `6744`) is already a benign data race among projection workers today; when threading changes, make it `thread_local` and pre-init `heightRef_`/scales once before the parallel pass. Out of scope for sim/render correctness but flagged.
10. **Session lifetime** — the sim thread must be **joined before `mp_->disconnect()` (`11170`) and before `world_`/`GameView` teardown** (`11151/11458`). `menuRequested_`/`quitRequested_` is the stop signal → join → disconnect. Rejoin/spectate reset (`mpAutoStep 3029-3052`: `resetForReplay` + counters + rebuild + synchronous `mpStep`) re-mutates `world_` mid-session — run that whole branch **on the sim thread** so `world_` keeps a single writer.

**Determinism invariant:** nothing in the `Frame`/event path feeds back into `world_` or `stateHash()`. `vis_` is already non-hashed (headless referee skips `updateVisibility`). So the snapshot is pure output — the `--mpai` hash cannot change from this work. That is the acceptance test for every stage.

**Stage B — move the InGame net/sim loop onto its own thread.**

**Stage C (optional follow-up) — polish.** `thread_local` height memo (#9); projectile sub-tick extrapolation; seqlock instead of mutex on the command queue if profiling shows contention.

## 5. RISKS / UNKNOWNS

- **Per-tick event ordering vs. multi-tick catch-up.** During rejoin/spectate fast-forward the sim processes many ticks per render frame. The durable `Frame` is last-writer-wins, but hits/justFired/justBuilt must drain per tick or effects/sounds double or vanish. The event queue must be bounded/coalesced sensibly during a big backlog (matches today's behaviour where `cosmeticStep` runs once after the whole drain — decide whether backlog events are played or dropped; today they are effectively collapsed). Get this explicitly right; it's the subtlest correctness point.
- **Snapshot cost.** Copying units+projectiles+features+fog every tick at 30Hz. Fog is the biggest (`visW*visH` bytes) but gated by `visGen` (copy only when changed). Units carry small vectors (`buildQueue`/`orders`/`cargo`) — measure; if hot, pool the `Frame` allocations (reuse buffers, as `geomPool_` already does) rather than fresh-allocating per tick.
- **`interp_` seeding across the buffer swap.** The teleport-reseed logic (`3495-3499`) reads `s.cx/s.cz` from the previous tick — ensure the double-buffer preserves prev-tick state correctly (swap, don't clear) or units zip across the map on the first frame after publish.
- **`MpClient` single-owner assumption.** Verified no locking today, but audit that *nothing* on the render side calls `mp_` after handoff — including error/teardown paths and any spectator UI. A stray render-side `mp_` call is a silent heap race.
- **Lobby→InGame→lobby round trips.** Return-to-menu (outer loop `11151/11458`) destroys and can rebuild `GameView`/`world_`. The sim thread must be fully joined and the `Frame` publisher reset between sessions; a leftover published pointer into a destroyed `world_`-derived `Frame` is a use-after-free.
- **`canPlace`/target-scan authority split.** Ghost preview reads the snapshot (stale by one tick — acceptable), but the actual emit validates on the sim thread. Confirm the sim-side validation matches what the player saw closely enough that legitimate placements aren't rejected on a one-tick-stale highlight (retail tolerates this; verify in play).
- **Determinism regression detection.** The `--mpai` hash guards sim state, but `vis_`/interp are *not* hashed — a subtle fog or interp bug won't trip the hash. Stage A/B need a visual smoke pass (a short recorded play session compared frame-to-frame), not just the hash, to catch snapshot field omissions.

Key files: sim types `src/sim/sim.h:193-458`; the loop + all reads `src/client/main.cpp` (`mpStep 2694`, `simStep 3319`, `captureInterp 3488`, `interpPose 3508`, `cosmeticStep 3527`, `buildUnitGeom 6020`, `unitScreen 6810`, HUD `8300-10110`, input `2247-2560/7130-7300`, fog/projectiles/minimap `3969-4316/7089/10019`); net `src/net/client.{h,cpp}`.
